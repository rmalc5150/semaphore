Start and stop behavior

The controller on t3 takes the shared lifecycle lock, starts m7 if needed, waits for SSM readiness, and dispatches the allowed worker unit. The shared autostop timer checks approximately every five minutes. Eligible historical backlog, enabled metadata backlog, unfinished summary jobs, local dispatch activity and active remote worker services keep m7 running. After ten minutes of shared idle, it checks again before stopping EC2. An activity-check failure does not authorize shutdown.

Current wake-up behavior: each metadata-controller cycle unconditionally dispatches the metadata publisher before discovery. That cycle can wake m7 even when its queues are empty. The shared guard protects shutdown; startup is currently driven by these timers as well as work dispatch, rather than exclusively by a nonempty backlog.

Data and publication boundaries

Collectors preserve original evidence and commit manifests/checkpoints in S3. Metadata workers validate committed inputs, retain provenance, write labelled outputs and record entities/evidence links in the current metadata registry. Publishers prepare curated releases, register Glue partitions and verify Athena counts/readback; immutable receipts establish successful publication. RDS holds the transactional queues and graph. S3 holds source bytes, derived data and operational objects. Some provider budgets are RDS-backed; EODHD shares a single conditional-write S3 counter across the two hosts.

Owner controls and later stages

Configured source pauses: reddit, bluesky_search, bluesky_company_accounts, bluesky_company_posts, bluesky_company_events, github_sdk, marketaux. The abandoned tracking dependencies and their catalogue/matching jobs are retired. Product search uses the current metadata_engine registry and awaits eligible product entities. Event pipelines, specialist models, HMM and TFT training/testing have monitoring registry entries, but no corresponding services were found on either inspected host.

Processing placement: market/news APIs, people, SAM.gov, small API capture and daily readback remain on t3. Ten additional bounded capture lanes, including EDINET, patent/assignment processing, EODHD profiles, Federal Register and NIST documents, join the publishers, committed-Athena, historical pools, metadata workers and queued summaries on m7. This schematic does not assert complete historical coverage or that every source error has been resolved.

Verification notes

Based on live EC2/RDS descriptions, systemd inventories on both hosts, the independent Lambda/Scheduler configuration and the current lifecycle, queue, metadata and monitoring code. The m7 worker pool has an aggregate two-vCPU quota and 6.76 GiB hard memory limit, leaving memory for Linux and system services. Its 20 GiB work volume contains code, local indexes and working files. Older historical-module labels that say “c7i” refer to routes now executing on the identified m7i.large instance. SNS acceptance and actual email/SMS delivery are distinct observations.
