## Evidence and status meanings

The [live audit](data-collection-processing/reports/specialist-source-audit-2026-10-05.json) reads current Glue tables/columns, Athena workgroups and recent query receipts, S3 progress checkpoints, health records and systemd timers. Nine catalog databases exist and have recent successful queries; `optima_social_research` is configured locally but **absent from Glue**. This audit did not run new Athena scans or authenticated provider requests. Existing successful query receipts establish bounded publication checks, not this week's full coverage acceptance.

The [September 25 coverage register](data-collection-processing/SOURCE_COVERAGE_REGISTER.md), [end-to-end verification](data-collection-processing/SOURCE_END_TO_END_VERIFICATION.md), current collector/configuration files and [October 5 repair evidence](data-collection-processing/reports/collection-repair-2026-10-05.md) supply the remaining status evidence. Proposed access routes come from the existing collection plan; each still needs an actual retrieval/access check unless marked collected. DataForSEO, PubMed, Europe PMC, NICE and NIH documentation were additionally checked for this update.

- **Have: partial** means some records/evidence exist, not all required fields or companies.
- **Have: not verified** means no accepted collection/publication evidence was found; an account or script alone does not establish holdings.
- **History: no** means required historical coverage is incomplete or unverified. Default target is January 1, 2021 onward, with older pivotal/baseline evidence where needed and explicit source/listing limits.
- **Daily: yes** means a recurring path is enabled and has collected data. It does not promise that every source/entity is current. **No verified start** means a new path or schedule is still required.
- For monthly, annual or release-driven sources, use **daily change checks or source-cadence capture**; do not manufacture a new daily observation from an unchanged release.
- Athena codes **Q1–Q9** resolve to exact existing tables below. **None** means no verified queryable dataset for that source; it must pass raw capture, normalization, publication and a query check first.

## How to verify we have everything required

Apply these checks to **every source row**, together with its final-column checks. The acceptance unit is a declared source scope, not an entire provider's unknown universe.

1. **Freeze requirements.** Record required companies/listings/products/trials/sites/projects, jurisdictions, languages, fields, source queries and date ranges. Start with all collection-enabled candidates in the appropriate reviewed universe; differences between collector universe versions require reconciliation. Mark truly optional enrichments separately. Three companies per sector is a pilot sample, not the final denominator.
2. **Prove access and provenance.** Retrieve a bounded real sample; record endpoint, entitlement, reusable fields, source ID/URL, retrieval time, raw S3 key, checksum and collector version. Check reuse/model-training rights where relevant. Account credits, an API description and a working HTTP response are insufficient alone.
3. **Reconcile the expected inventory.** Construct expected entities × windows/editions/sessions/queries. Join it to committed manifests and publication receipts. List missing, partial, failed, verified-empty, excluded and unavailable windows separately. Min/max dates and nonzero row counts do not prove intervening coverage. Exclusions need exact boundaries and saved proof; retain them in the denominator with their reason.
4. **Verify records and required fields.** Check pagination exhaustion/counts, stable IDs, duplicates, corrections and replay/resume. Inspect original evidence for each critical field; compare requested vs populated fields and unit/date types. Track textless PDF pages as skipped extraction without creating an alert, per existing policy; they still lower completeness.
5. **Reconcile raw → curated → Athena.** Verify raw batch hashes/counts; review entity joins; compare curated counts to accepted manifest records and table partitions. Deduplicate versions intentionally. Do not sum a parent table and its type-specific subsets. Save Athena query IDs, actual/expected counts and mismatches.
6. **Prove usable history.** Record the verified usable start/end and gaps for each entity/query, not only the collector cursor. Preserve original publication, source revision, first observation and availability dates. Current snapshots, later corrections and today's constituent list cannot be backdated into training history. Backfills are complete only when every required window passes or has an explicitly accepted scoped limitation.
7. **Prove ongoing capture.** Confirm enabled timer, actual successful retrieval, committed checkpoint movement, publication and a repeat run with no loss/duplication. Compare freshness to the source's release cadence. A queued timer, metadata-only monitor or successful empty process is not enough. Perform a controlled retry/replay check without disrupting production services.
8. **Record a decision and next action.** Each source gets `ready`, `partial`, `blocked`, `not_started`, `unavailable_publicly` or `not_applicable`, plus evidence, owner, blocker, remaining windows and a review date. A readiness report must show every required missing input; incomplete rows cannot silently disappear.

Recommended per-source acceptance record:

```text
source_id, required_entities_or_query_set, universe_version, jurisdictions,
required_fields, required_start, required_end_exclusive, source_cadence,
verified_usable_start, verified_usable_end, expected_windows, completed_windows,
verified_empty_windows, excluded_windows, unavailable_windows, failed_windows,
unattempted_windows, raw_manifest_keys, publication_receipts, athena_database,
athena_table, partition_ids, verification_query_ids, latest_committed_at,
latest_published_at, history_complete, recurring_capture_verified,
rights_and_availability_limits, status, blocker, owner, next_action, review_date
```

There are also **derived deliverables**, not additional external sources: normalized financial/transaction/milestone histories; entity/product/trial/site/person/project links; total-return/benchmark/FX labels; point-in-time feature panels; coverage and evaluation/split manifests. Existing source records do not prove these are implemented. Validate their joins, timing, denominators and evidence lineage separately. Keep EC2 dataset preparation to one consolidated daily run; model training remains on Windows.
